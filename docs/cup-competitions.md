# Cup acquisition

The reviewed 2026 scope adds fourteen cups to the existing ten leagues: UEFA Champions League, Europa League, Conference League, English FA Cup and League Cup, DFB Pokal, KNVB Beker, Belgian Cup, Copa del Rey, Coppa Italia, both Portuguese cups and both Scottish cups. The initial verified archive contained 1,803 fixtures. France's 2026 Coupe de France was absent from provider metadata and remains outside this scope.

The protected `cup_catalog_publish` operation initializes competition/season identities from hashed R2 snapshots. It writes no fixture details and supports cups with over 100 teams or a December season end without changing the old league migration gates. The normal fixture publisher then creates fixture/team/player records and publishes lineups, events, team/player statistics and ratings using the existing correction handling and shared ledger.

The existing live Worker and GitHub acquisition job cover all 24 competitions. Shared today/tomorrow discovery runs every fifteen minutes, including newly drawn cup ties without a core schedule row. Existing kickoff checks, announced lineup polling, live polling, disappearing-match confirmation, provisional final details and core final precedence apply to cups. A final observed during date discovery also updates the stored score/details. Live limits remain twelve provider requests per tick, 4,000 per day and a 1,200-request provider reserve.

The existing fifteen-minute final automation discovers yesterday/today/tomorrow, retains due work and uses the same initial/6h/24h/72h correction stages. All leagues and cups share the existing 20-per-run and 40-per-day automated detail limits and the global publication ledger. UEFA tables join the existing six-hour standings rotation; knockout-only cups never request tables. Enabling this flow does not mean all historical cup details have already been acquired.

The existing four-hour schedule synchronization also refreshes complete cup seasons and UEFA tables. `scripts/cups/refresh.mjs` preserves the provider reserve, validates the returned reviewed identities, refuses lost fixture IDs, changed club identities, older timestamps or missing previously acquired standings, archives the raw response, verifies content-addressed R2 uploads and updates the catalog last. A main publication workflow performs the same guarded refresh when cup configuration or scripts change.

Cup season/date routes merge the full R2 schedule with published D1 results and player aggregates. D1 failure leaves an observable degraded schedule. The ordinary global daily feed includes stored cup fixtures; protected `fresh=1` D1 audit routes retain their exact core inventory contract. The directory keeps full schedule counts after catalog initialization. The UI polls stored live data and the open cup season every minute while visible, preserves the selected filter and opens the existing common fixture detail page. Viewers never call API-Football. Missing provider sections remain explicit.

Validation includes scope/budget planning, partial-refresh rejection, protected metadata plus normal final publication and public reads, CL/EL/Conference/domestic lineup-goal-PK transitions, cup screen polling, and native workerd/D1 GitHub dispatch/acquisition/public-read replay with a cup fixture absent from core inventory.
