### 1.3 共通の状態表示（全画面・省略不可）

矛盾時は `screen-flow` §8 を優先する。

| 状態 | 表示 | 禁止 |
|---|---|---|
| 初回 loading | 対象領域の loading | 前画面の値を新 ID の値として残す |
| 空配列 + `presence: present` | 該当なし | 「未取得」と表示する |
| `not_fetched` | 未取得（破線 + パルス） | 0件・0・欠場へ変換する |
| `not_applicable` / `provider_missing` | **非該当（統合表示・判断確定）** | 一般エラーと混同する |
| archive loading | 通常の詳細 loading | archive 専用画面へ飛ばす |
| detail unavailable | **スコアを残し**「詳細は取得できません」 | 試合が存在しないと表示する |
| 404 entity | 対象なし + 戻り先 | 空の正常画面に見せる |
| 409 review required | データ確認中 | 補正値で黙って上書きする |
| 429 | 待機案内 + retry | API quota を利用者へ露出する |
| 5xx / offline | 再試行 + 最終成功時刻 | 別日・別 entity の cache を代用する |

**表示値 `0` と欠落を同じ見た目にしない。** 要因分解でも未取得を `±0.00` と書かず「未取得」とする。

**試合状態の色分け**: LIVE = 赤塗り + パルスドット（**赤はこの状態専用**） / 終了 = 緑 / 開催前 = 背景なしの `--muted` テキスト / 中止 = 打ち消し線。スコアヘッダと `状態 > ステータス` 行の両方で分岐する。

### 1.5 視聴価値ランキングの表示仕様

スコアは3層で決まる。

```
displayed_score          = round2(base_score × 2^(-経過時間 / 168h))   ← 半減期7日
follow_multiplier        = min(1.25,
                             1.00
                           + (フォロー中の選手が出場 ? 0.15 : 0)
                           + (フォロー中のクラブが対戦 ? 0.10 : 0))
personal_displayed_score = round2(displayed_score × follow_multiplier)
```

- サーバは中立 `displayed_score >= 16.00` の候補を返す
- ブラウザが follow 係数を掛け、`personal_displayed_score >= 20.00` に絞り直す
- **フォロー情報をサーバへ送らない**
- 係数は表示順と表示閾値だけに使い、`base_score` と中立順位を変えない
- 係数 1.00 の行にフォローラベルを出さない
- `attention_version` を明示する（同一時刻・同一入力での再現に使う）

**未算出の扱い**: 必須入力が欠けた試合は `base_score = NULL` となりランキングから除外する。ただし「価値なし」「0点」と表示せず、**未算出として除外表示**する。試合詳細では「視聴価値は未算出」と表示する。

**取得中の扱い**: 全ページ取得後に follow 係数を適用する。途中ページだけで最終順位・件数を確定表示せず、**全候補取得中であることを示す**。

### 1.6 tracking insights の表示仕様

監視パイプラインが生成する注釈。**数値の根拠として扱わず、`confidence` と出典を併記して数値順位から分離する。**

配置は2箇所。

**日本人タブ「好調・注目ポイント」**（legacy `#insights` の統合先）

リード文: 根拠がある項目のみ表示。事実と分析を分離。

| カード | 由来 | 構成 |
|---|---|---|
| 事実カード | `insights[]` | 見出し / 確認できた事実 / なぜ注目か / 出典 |
| 分析カード | `analysis[]` | 見出し + 確信度 pill / 本文 / 出典 |

事実カードと分析カードは視覚的に別物にする（事実 = 確認済み、分析 = 推測）。既存トークンの範囲で差をつけ、新色を作らない。

**`confidence: low` の分析カードは既定で折りたたむ（判断確定）。** high / medium は展開、low は「もっと見る（n件）」で開く。

空状態: 現時点で、掲載に足る根拠のある好調・分析項目はありません。

**選手詳細「どんな選手か」**（所属履歴の前）

その選手に紐づく insights / analysis のみ。事実カードは「確認できた事実」/「注目点」の2ブロック（日本人タブの「なぜ注目か」と文言が異なる。legacy 準拠）。

空状態: プレースタイルを断定できる詳細データはまだありません。

### AI 分析機能について（保留の経緯）

「試合データから AI に深く聞く」機能を検討したが、**今回のワイヤーフレーム範囲外**として保留した。検討した選択肢と評価を記録しておく。

| 案 | 深さ | コスト | 既存仕様との相性 |
|---|---|---|---|
| A 事前生成を観点別に増やす | 低 | 予測可能 | ◎ `confidence` / 出典を人手確認できる |
| B オンデマンド Q&A（自由記述） | 高 | **読めない** | △ 出典を機械的に付けられない |
| C 質問テンプレート + キャッシュ | 中〜高 | ほぼ A 並み | ○ |
| D エクスポート導線（生成しない） | 高（他人の AI） | ゼロ | ◎ 抵触しない |
| E MCP サーバとして公開 | 最高 | 読み取りのみ | ◎ 対象は狭い |

**B は非推奨**。GitHub Pages の公開サイトで認証が無いため、誰でも叩ける構造になり課金上限が読めない。

**推奨は D → C の順**。D はコスト0で即出せるため需要を測れる。需要が確認できてから C に投資すれば外れたときの損が小さい。

どの案でも守る線: **LLM の判断や生成文を順位計算へ入れない**（`attention-score` §1）。AI 出力は注釈であって数値ではない。
