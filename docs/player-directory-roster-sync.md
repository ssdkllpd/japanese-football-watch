# 選手ディレクトリと名簿の更新

## 保存内容

- `players` は API-Football の選手 ID を本人のキーとして、国籍・生年月日・写真を保持する。既存の試合取込でプロフィール値が欠けても、取得済みの国籍を消さない。
- `player_roster_observations` はチーム名簿・シーズン選手ページでその日に確認した所属を保持する。`observed_on` は移籍日ではない。`player_roster_sync_runs` の完了した最新実行だけを現在の名簿表示に使い、消えた選手の旧所属は履歴に残す。試合当日の所属は `fixture_player_records.team_id` を使う。
- `/api/v2/players?nationality=Japan` は日本国籍が確認された選手を返す。`nationality=all` と `team=af:team:<id>`、`after=<providerId>` にも対応する。100人ずつ取得する。未取得の国籍を日本国籍と推定しない。
- `/api/v2/players/af:player:<id>` は本人のプロフィールと名簿で確認したクラブ履歴を返す。大会の `playerStats.teamRows` は試合当時のチーム別成績であり、移籍後の所属名簿には左右されない。

## 自動更新

`.github/workflows/api-football-player-roster-sync.yml` は初回マージ時と毎週日曜 02:17 UTC に対象10リーグの全選手ページと全クラブ名簿を読み取る。選手ページに出ない名簿選手は2026年、該当しなければ2025年の選手ID照会で国籍を補う。全10リーグの取得が完了し、選手数・チーム数・API残量・D1月間書込予算の確認が通った場合だけ、管理Workerに40人ずつ送る。API残量500件を常に確保する。手動起動は `preview` と `execute`（確認文字列 `RUN PLAYER ROSTER SYNC`）を選べる。

途中で送信が失敗するとその実行は未完了のままで現在名簿に反映されない。翌週または手動実行で別の実行IDとして再取得し、全選手IDを照合してから完了印を付ける。試合結果を再取得する処理ではない。

## 従来プロフィール

旧64人全員の API-Football ID を `tracked-player-provider-ids.js` に明示した。伊藤涼太郎は2024年STVV選手ページ、神代慶人はAPIの氏名・日本国籍プロフィールで照合した。確認済みの試合成績を旧日本語プロフィールにも表示し、国籍一覧では同じ人を重複させない。現在の出場・所属が取れない場合はIDから数値を推測しない。小川航基のIDは2025年のNEC選手ページで確認したが、2026年の対象10リーグ外の移籍先を追跡対象には加えない。

新規加入者は固定表へ追加せず、APIから得た選手IDと国籍で一覧へ入る。国籍未取得の名簿選手は「すべて」には表示されるが、日本人絞り込みには入らない。対象リーグから離れた選手の過去の試合記録は残る。
